PunktNameChanger Function Notes

This project renames Leica survey point IDs in `.imes`, `.ipkt`, `.iroh`, and
`.lqp` files while preserving file formatting and validating coordinates against
a selected master file.

Source of truth:

- Single-file mobile app: `Punkt-Name-Changer.html`
- Standalone duplicate diagnostic: `IPKT-Coordinate-Duplicate-Checker.html`
- Standalone arbitrary-group renamer: `IPKT-Group-Path-Renamer.html`
- Split implementation: `js/utils.js`, `js/parsers.js`, `js/renamer.js`, `js/main.js`
- Regression tests: `tests/run_validation.py`
- Security and deployment guidance: `SECURITY.md`
- Optional generated single-file build: `scripts/build_singlefile_dist.py`

Core behavior:

- The standalone IPKT coordinate duplicate checker compares every valid `YXZ`
  record by Y/X coordinates, defaults to a `0.10 m` tolerance for each
  component, groups identical or probable near-duplicate matches, displays
  point IDs and source line references, and exports a detailed TXT report with
  generated date/time, source filename, duplicate groups, and direct matching
  pairs without modifying or uploading the source file.
- The standalone IPKT group path renamer discovers arbitrary point families by
  their final numeric index, lets each family be configured as `P`, `G`, `Q`,
  or `QL`, and exports both normalized path IDs and final MQ names using the
  existing source-index-based MQ and suffix rules. It replaces only raw ASCII
  point-field bytes so all other source bytes and fixed-width alignment remain
  unchanged. Direct final-MQ output applies the existing `-0.04 m` Q/QL prism
  height correction. Its enabled-by-default coordinate gap check compares
  consecutive section centers and advances by the larger of the source-index
  step or `round(distance / configured normal step)`, preserving MQ numbers
  when measured sections were skipped. Optional bridge detection suppresses
  coordinate-derived MQ skips for a large span or consecutive run of large
  spans only when short measured approaches bound the complete span on both
  sides. It detects every separate bounded bridge in a group, including two or
  more bridges, and numbers them in the TXT report. The compact Type selector
  contains only `G`, `P`, `Q`, and `QL`, with a legend above the table. A live
  MQ line schematic uses the same export plan to show measured, missing, and
  bridge sections for every enabled group. During group discovery, it also
  checks every valid `YXZ` record for duplicate Y/X coordinates, displays the
  results below the configuration, and exports a separate detailed duplicate
  TXT log.
- In the group path renamer, a source group explicitly ending in `.EX` uses
  automatic coordinate-anchored EX mapping. Its first point starts at the
  nearest configured `P` or `G` MQ. Four EX positions normally share an MQ;
  the MQ immediately before and after each detected large bridge gap uses two
  positions, with one MQ reserved across the bridge. The editable final prefix
  defaults to the source-family prefix and updates both EX exports and the live
  proposed MQ schematic. The EX schematic displays every calculated position,
  such as `MQ19-1` through `MQ19-4`, including missing positions and reserved
  bridge MQs. Skipped EX indexes keep their position, and export fails instead
  of falling back to `MQ01` when no coordinate anchor exists.
- The optional `scripts/normalize_leica_point_ids.py` preprocessor converts a
  configured prism series such as `101.1` into `P01.001` while
  preserving pipe-file alignment. IDs explicitly containing `.EX.` always use
  the fixed bridge-interruption calculation: `EX.14 -> MQ22-2`,
  `EX.15 -> MQ24-1`, `EX.16 -> MQ24-2`, and `EX.17 -> MQ25-1`.
  This special calculation does not affect ordinary numeric point IDs.
- The separate `scripts/normalize_gleis_point_prefix.py` mini-script converts
  Gleis IDs into three-digit project format while preserving the fixed-width
  pipe-file layout. Source pairs normally advance by two MQ positions, but
  source points `G101.19..36` use consecutive MQs. After point 36, the
  every-other-MQ sequence resumes.
- The dedicated `scripts/normalize_20260613_point_ids.py` mini-script maps
  prism families `2505.1` to `P02`, `2500.1` to `P03`, `2504.2` to `P04`,
  and `2504.1` to `P05`.
  Every explicit EX sequence, including a different family such as `101.EX`,
  ends the first section at `MQ22-2`, jumps to `MQ24-1/2`, and resumes
  four-position groups from `MQ25-1`.
- Supported point IDs use dot format only: `G01.001..G10.998`,
  `P01.001..P10.998`, `Q01.001..Q10.998`, and
  `QL01.001..QL10.998`.
- `G` odd points receive suffix `3`; `G` even points receive suffix `4`.
- `P` odd points receive suffix `1`; `P` even points receive suffix `2`.
- Final output suffix codes are single digits without leading zeroes.
- `Q` groups map four source points to one MQ: positions 1/2 use suffixes
  `3`/`4`, positions 3/4 use suffixes `1`/`2`.
- `QL` groups map four source points to one MQ: positions 1/2/3/4 use
  suffixes `1`/`3`/`4`/`2`.
- Quadro prism positions subtract `0.04 m` from the existing height field
  during rename.
- Quadro path numbers behave like `G` and `P` path numbers. Quadro section
  numbers come from the source index groups: `001..004`, `005..008`, and so on.
- Pattern mode starts at the configured source point and stops exactly at QTY.
- Coordinate checks must pass before a point is renamed.
- Replacement text is padded to preserve the original field width.
- Unsupported extensions are skipped before reading.
- Input files over 10 MB are skipped, and one selected session is capped at 30 MB total.
- Pattern base prefixes and output suffixes may contain only letters, numbers, dot, underscore, and hyphen.
- Files stay local in the browser session; no remote API, analytics, cookies, or browser storage are used.
- Content Security Policy metadata blocks network connections and object embedding.
- Busy status disables main action controls during file reads and rename runs.
- Export summary reports loaded files, modified files, and TXT log entries.
- The generated single-file build script writes only to `dist/` and does not modify `Punkt-Name-Changer.html`.

MQ numbering rule:

MQ is based on the original source point pair index:

```text
G/P groupIndex  = floor((sourceIndex - 1) / 2)
Q/QL groupIndex = floor((sourceIndex - 1) / 4)
mqIndex = startMq + groupIndex - startGroupIndex
```

This is intentional. If a field file contains only the first part of a path and
then jumps to the end of the path, the final section keeps its real MQ numbers
instead of being numbered as the next measured rows.

Example with start point `G01.001` and start MQ `1`:

```text
G01.001 -> MQ01
G01.016 -> MQ08
G01.071 -> MQ36
G01.088 -> MQ44
```
